# 三端迁移与交互改进

## 为什么改

Android 选完备份文件后，导入预览里的合并、替换和取消按钮在竖排时紧贴。三个平台的旧版 InkOTP 加密备份入口已无使用需求。Google Authenticator 迁移链接目前只能被识别，无法完成批量迁移。打开验证码列表时，现有卡片缺少一次简短的入场反馈。

## 范围和验收方式

- Android、iOS 和 macOS 使用有间距的导入确认动作。默认合并，替换前再确认。检查小屏、长文案、放大字体、取消及并发操作。顺带检查扫码、照片、密码和导出后的状态。
- 删除三端对外旧版 `.2fab` 导入、导出及专用编解码路径。用仍受支持的 Aegis 加密备份验证加密导出与恢复。验证已有安装覆盖升级后仍能打开本地库。
- 通过 Google Authenticator 迁移二维码双向迁移。覆盖单码、多码、顺序、重复、混批、不支持字段、取消和原子提交。用合成公开密钥和独立生成的互通样本验证。真实 Google 客户端迁移按设备上的实际结果记录。
- 验证码卡片在列表首次进入时轻量下落并依次就位，检查系统减少动态效果、滚动、搜索、倒计时刷新和锁定。继续遵循 Quiet Ink 的字号、间距和色彩。
- 通过本机和 GitHub Actions 的三端门禁后，从统一标签发布，重新下载核对公开 Assets 和 SHA-256。

## 额外修复

macOS 之前在已解锁的导入流程中始终走合并。今后在第二次确认后可以替换本机账号，并保存本机安全设置。Android 的备份预览和破坏性确认分别展示，避免叠放。照片选择和 QR 读取完成时也会重新检查会话，防止旧操作结果进入新会话。

## 验证结果

独立生成的 14 项 Google 二维码用例覆盖版本 1 和 2、公开密钥、缺省字段、多页和错误输入。Swift 共用编解码器和 macOS 生产适配器的本机探针通过。原有 10 项上游交换文件、OTP 向量、库示例的独立 Argon2id/AES-GCM 检查与 46 项 Python 测试通过。Android 320dp 窄屏和 200% 字号的导入确认按钮检查通过。macOS 本机源码构建通过，正式签名产物由 Actions 生成。iOS 本机仅运行源代码语法检查。

三端标签运行、公开资产与真机专项待补验收结果。
