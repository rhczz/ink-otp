# 后续只维护 Android 版

## 为什么改

此前 Android、iOS 和 macOS 共用一个发布页。以后仅维护 Android，需要收口当前分支中的应用源码、构建、发布和用户文档，并让早先下载其他平台版本的用户仍能找到原有发布。

## 范围和验收

- 移除 iOS、macOS 应用源码、Apple 共用模块及专用构建测试。保留 Android 应用、Android 的 Google Authenticator 迁移和通用交换格式。
- 后续标签只构建并发布 Android 签名 APK 及发布元数据，保留覆盖安装依赖的签名身份和递增版本检查。核对新版发布不会把现有多平台发布误判为可重建的版本。
- 更新使用、开发、格式和发布文档，以及仓库中的官网下载与隐私说明。旧平台历史文档继续可从当时的提交和标签查看。
- 用 Android 本机检查、发布工具回归和工作流静态检查验收。改动通过正常 PR 提交。Git 历史、原标签和原 Release 不改动。

## 验证结果

- 当前分支移除了 `ios/`、`macos/`、`apple/` 和五个专用工作流，保留 Android CI 和 Android 发布工作流。现行文档及官网源码改为 Android 下载入口。旧平台规格通过固定历史提交查阅。
- 本机 `make ci` 全部通过，包括 APK 构建、覆盖率、Lint、权限、存储规则、16 KiB 对齐、交换文件独立校验及 45 项 Python 测试。两个工作流通过 actionlint 校验，按发布指南仅忽略旧 linter 对 GitHub 已支持的 `concurrency.queue` 字段的诊断。
- 用 Android Build Tools 和临时测试证书签名构建产物，复核四项发布资产、三条 SHA-256 校验、证书及同一运行重试。历史检查匹配了 10 个含 Android 的版本标签、4 个旧平台专用标签及 14 个 Release，拒绝重发已存在的版本。
- 本次改动走普通 Git 提交与 PR，保留原 Git 历史、标签与发布资产。官网改动在仓库源码内，本次未部署。未用正式签名执行新的标签发布。
