# 0.4 手机反馈：系统指纹入口、闪屏与到期颜色

## 为什么做

用户安装 0.4.0-beta.1 后反馈三项问题：指纹入口像自绘认证、设置每次操作闪屏、最后五秒仅倒计时明显变色；随后补充相册未询问部分/全部权限的疑问。这是 [M4 首版](2026-11-17-m4-standards-auth-performance.md) 的后续修复，按本机自动验证后交付 APK、再由用户真机复测。

## 实施前范围与验收

先同步权威设计 §10.4、§11.6、§11.7 与 [交互契约](../../spec/android-interaction.md)，再修改认证入口、共用进度反馈及列表/详情颜色。保留现有 Quiet Ink tokens、加密认证、并发门禁及后台隐私保护；不修改数据格式和测试夹具。

认证检查自动请求、取消不循环、主动重试、恢复口令回退、并发与过期结果；反馈检查快速/慢速/失败操作、触摸和返回拦截、取消/锁定后的清理；颜色检查浅深色、6/8 位、6→5→1→新周期及隐藏。按 Makefile 执行 core/App 测试、覆盖率、构建、Lint、Python 对拍与权限检查，再生成使用原签名且版本递增的 APK。升级兼容用现有格式回归与签名检查佐证，真机覆盖升级仍待用户验证。

## 原来怎样与排查证据

- `DeviceSecurity` 已使用 AndroidX BiometricPrompt + CryptoObject；自绘的是 `UnlockScreen` 的大指纹圆按钮。普通生物识别不会像“每次进入验证”那样自动调用系统界面，系统负按钮“使用恢复口令”也未直接切换表单。
- `VaultViewModel.perform` 对所有保存立即置 busy，`InkApp` 立即显示全屏 scrim 与 spinner。设置保存很快完成，屏幕因此瞬时变暗再恢复。页面主体没有被卸载，主题窗口背景一致。
- 列表最后五秒把数字换成 `inkSecondary`，详情一直用 `ink`；倒计时才用 `warning`。
- 相册使用 `ActivityResultContracts.GetContent`，由系统选择器返回选中的单个 URI。源码没有相册枚举，也没有广泛媒体或存储权限；不弹部分/全部访问权限是正常的按项授权流程，无法从电脑判断用户手机系统设置。保持当前规范流程，最终再核对 APK 合并权限。

## 现在怎样

解锁不再展示自绘大指纹圆按钮。已开启生物识别或每次进入验证时，前台就绪后每个锁定会话自动请求一次官方认证；取消、失败和旋转后由用户主动点“使用系统验证”重试。系统界面的“使用恢复口令”会直接切到应用口令表单。两条认证路径共用可观察的认证中状态、120 秒上限和后台处理，保留 CryptoObject 授权及旧结果拒绝，不获取手机锁屏密码。

保存、添加、编辑、排序、备份和文件读取仍立即进入 busy 门禁，透明拦截触摸与返回，但不再改变整屏亮度。持续超过 300ms 才显示局部进度；认证期间不叠加应用进度。操作序号让连续操作重新等待，完成、失败、锁定或取消会清理提示。后台隐私遮挡继续保留。

列表与详情 TOTP 剩余 ≤5 秒使用已有 warning 色，新周期恢复 ink；隐藏码继续隐藏，HOTP 占位保持中性色。版本提升为 `0.4.1-beta.1` / versionCode 4，沿用既有签名与全部数据格式。

升级版本时还发现发布工具测试依赖工作区里写死的旧版本源码，导致四个既有用例没有进入预期的签名/历史检查路径。测试现使用独立临时源码树固定场景，生产发布工具和 spec 夹具未改变；Python 42 项已全部通过。

## 如何验证与限制

修复前的回归已实际失败：认证 16 项中 4 项检出普通认证不自动请求、认证中标记缺失、无超时与旧自绘入口；设置真实保存流程 3 项中 1 项检出背景从 `#F6F7F9` 暗成约 `#6F6F70`；倒计时实际文本颜色检出列表为 secondary、详情为 ink。倒计时修复后 4 项通过，涵盖浅深色、6/8 位、6→5→1→30 秒、隐藏/显示与 HOTP。
