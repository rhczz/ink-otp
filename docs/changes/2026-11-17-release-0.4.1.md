# 0.4.1 GitHub 发布与下载复核

## 为什么发布

[0.4 手机反馈修复](2026-11-17-phone-feedback-fixes.md) 已完成本机验证并交付 APK。用户询问远端版本后，明确要求“发布”；因此本次将同一轮修复提交到 `rhczz/ink-otp`，使用现有 tag 流水线生成 GitHub 可下载安装包，不更换签名或修改备份格式。

## 发布前范围与验收

发布版本为 `0.4.1-beta.1` / versionCode 4，tag 为 `v0.4.1-beta.1`。本机已有 core 105、App 150、Python 42 项通过及 Debug/Release 构建、Lint、权限、签名与对齐证据，实际覆盖率见原修复记录。发布前再次只读核对远端主分支、既有 Release 和 tag，避免重复版本或覆盖更新；现有用户账号存储说明及其索引修改保持在本机，不混入功能发布提交。

验收要求是：远端真实质量门禁通过，签名与发布 job 成功，Release 存在且包含 APK、SHA256SUMS、build-info.json、release-notes.md 四个文件；下载这些文件后，复用发布工具检查哈希、tag/源码/运行来源、版本、固定证书、非调试、权限、ABI 和 16 KiB 对齐。发布失败不能记录为已完成，也不能用本机 APK 代替远端成功证明。

## 原来怎样与现在怎样

发布前远端只有 `v0.4.0-beta.1`。0.4.1 修复尚未提交或打 tag，所以没有触发发布。这次更新发布说明，去掉只适用于本地交付阶段的“尚未发布”状态；提交修复后推送递增版本 tag，沿用既有 CI、固定签名与 GitHub Release 流程。

## 实际结果与限制

执行中：提交、tag、远端流水线及下载核验的实际结果将在完成后补充。真机系统认证样式/触觉、连续点击帧连续性、保留账号的覆盖升级、选图/取消及手机性能仍未验证，继续由用户安装后反馈；发布成功不代表 M3/M4 真机验收完成。
