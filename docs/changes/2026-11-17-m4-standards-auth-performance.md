# M4 内测：标准互通、每次进入验证与性能收口

日期：2026-11-17。状态：已交付 0.4.0-beta.1，真实 GitHub CI 与 tag 发布通过；手机专项验证待用户反馈。

## 用户希望得到什么

M3 已在用户手机初步试用，暂未发现大的问题。本轮继续完善，重点是：遵循成熟生态与 Android 标准，普通卸载尽可能完整清理应用拥有的数据；可选每次进入时使用手机自己的验证方式；备份能与常见验证器互通；功能、异常、性能和资源占用都要有检查与记录。

用户说的“覆盖全、性能基本完美”落实为可审核的验证范围和指标：逐项覆盖关键业务路径、输出真实覆盖率及基准结果；相机、系统认证、厂商存储和耗电仍须真机验证，不能用 Mac 的速度替代手机结果。

## 本轮交付顺序

| 工作 | 用户可见结果 | 验收方式 |
|---|---|---|
| 标准与兼容矩阵 | 明确采用哪些官方机制、支持哪些备份格式 | 源码/Manifest 断言、格式规格与独立夹具 |
| 系统身份验证 | 开关开启后，每次正常进入都通过系统指纹/强人脸或锁屏凭据确认 | 启用、关闭、取消、冷启动、后台返回、旋转、选择器、密钥失效和升级测试；真实弹窗待手机确认 |
| 双向备份互通 | 常见生态格式和 otpauth 文本可导入导出，旧 .2fab 继续读取 | 官方样本导入、独立实现解读导出、错误口令/损坏/超限/未知类型测试 |
| 性能与资源 | 前台按需刷新，锁定/后台停止无用轮询，出码按周期缓存 | 500/1000 条目基线、HMAC 次数与缓存上限、时钟边界、按需资源采样 |
| 完整回归与 APK | 固定签名覆盖升级，安装包和测试说明 | core/App 单测、真实行/分支覆盖率、Lint、权限、Release 签名和体积检查 |

## 决策与边界

- 本机库和旧备份 v1 不改变字节布局，保证 M3 数据与备份可读。新的交换格式写在 `spec/interoperability.md`，不把 Android 的本地验证策略写入跨平台库格式。
- 系统验证用独立、持久的本机策略。开启前要求先有恢复口令；手机锁屏密码仅在系统界面输入，不会进入 InkOTP。关闭也需要新的系统确认。
- API 30+ 使用支持强生物识别和设备凭据的官方 BiometricPrompt 与认证绑定密钥；API 26–29 使用标准 Keyguard 凭据确认与短时认证绑定密钥，不强行调用旧版不支持的组合。
- 策略与设备信封分开保存。包装损坏、改口令或导入不能静默关闭验证；失效后需系统确认和恢复口令重新建立包装。
- 普通后台返回在开启此开关时强制重新验证；旋转不算重新进入，用户明确发起的系统文件选择流程保留有期限的单次例外。
- 用户导出的备份继续由用户拥有；不能用卸载广播做不可靠的最后清理，更不能为了“卸载干净”删除用户在共享目录或网盘保存的文件。
- 不存在已确认的通用加密 OTP 备份标准。本轮按成熟项目的公开格式互通，支持范围以实际夹具验证为准；格式不支持时明确拒绝，不静默删字段/条目。

## 测试与性能计划

在现有 RFC、库格式、仓储、生命周期和界面回归基础上，增加新格式双向与损坏输入、认证新策略和迁移、卸载相关存储配置检查。新增 App 覆盖率报告；核心保留至少 90% 的已有行覆盖率门禁，关键新逻辑检查分支遗漏并补测试。

性能先记录当前 250ms 轮询和每秒全量 HMAC 的基线，再检查按周期缓存后的 500/1000 条目表现。基准单独运行，报告 p50/p95 与可测分配量；时间数字用于本机趋势，不冒充手机门禁。确定性门禁检查无多余 HMAC、后台无出码任务、缓存有上限、锁定清缓存、解析输入有大小限制。

App 性能与资源诊断仅按需读取 PSS/堆和私有存储大小，不采集账号、密钥、验证码或完整文件路径，不产生后台监控服务或联网遥测。

## 实际结果

### 用户实际会看到的变化

设置新增“每次进入时验证身份”。启用和关闭都调用系统确认，不在 App 内收集手机密码；开启后普通后台返回不能沿用原来的 30/60 秒宽限。设备包装失效、改恢复口令或导入后，策略仍保留；必要时直接展示应用恢复口令输入，再调用系统认证重绑。

导出默认选 Aegis 加密备份，可主动选择 2FAS、明文迁移或旧版 `.2fab`。导入自动识别内容，预览来源格式、冲突和损失说明，再由用户选合并或替换；本机恢复口令保留。明文导出需验证当前应用恢复口令，并再次确认完整密钥会写入文件，取消即清理暂存。

诊断页提供按需资源采样。相机能力均声明为可选，避免相机权限隐含“必须有后置摄像头”，影响只使用手动输入的设备。

### 本轮发现并修复的边界

- 系统认证后台例外使用绝对 120 秒截止时间，重复 `onStop` 不续期；自动尝试标记归 VM 内存，旋转不重复弹框，新进程重新尝试。
- 系统策略刚持久化后如果其他元数据读取失败，仍按保守策略处理，不能留下旧的后台宽限。
- 文件选择器有绝对 60 秒上限；返回顺序无论是先 `onResume` 还是先结果回调，都能恢复单一前台 ticker。
- 交换 JSON 预扫描同时限制深度、容器和分隔符预算，阻止大量标量在建树时耗尽内存；URI 逐行惰性解析，不物化数百万空行。独立 128 MiB JVM 中，约 6 MB / 300 万标量输入由 OOM 变为受控拒绝；约 12 MiB 空行输入能正常处理。
- 外部口令保持原始 Unicode，不能按本 App 的 NFC 规则改写别的验证器口令；2FAS 按官方排序字段导入，HOTP counter 不截断。
- `.2fas` 与通用文件类型配套，避免 JSON MIME 让 AOSP 保存器追加 `.json`；六种格式的 Intent、MIME、文件名与取消均有回归。
- 资源和文件测试覆盖真实 Context、内容提供器读写、12 MiB 边界、空描述符、IO 异常、流关闭和不泄露路径；测试中识别了 Robolectric 空 supplier 的默认占位流行为，改用实际空描述符 provider 验证生产分支。

### 验证证据与限制

现有和新增 core/App 测试、独立 Python OTP/备份/互通对拍、存储配置变异回归均已运行；最终完整测试和覆盖率见下表。51 张页面渲染覆盖明暗模式与 200% 字号，新增系统验证、恢复重绑和资源状态，人工查看了关键样张。渲染不等同系统认证硬件验收。

### 性能结果

首轮归档基准（后续 CI 趋势单独保存）：[m4-host-performance.json](../testing/m4-host-performance.json)。环境是本机 macOS arm64 / OpenJDK 25.0.5，同进程预热后各场景 300 样本；分配量来自当前线程，不是持有堆或手机 PSS。

| 账号数 | 原每秒全量计算 p95 | 缓存后普通倒计时 p95 | 跨周期全量换码 p95 | 普通刷新分配量：原 → 缓存后 |
|---|---:|---:|---:|---:|
| 500 | 0.303083 ms | 0.018083 ms | 0.395459 ms | 529249 → 30073 B |
| 1000 | 0.567667 ms | 0.020208 ms | 0.571875 ms | 1057273 → 60073 B |

固定 30 秒周期下，500 / 1000 账号每 30 秒 HMAC 从预期 15000 / 30000 次降为实测 500 / 1000 次，减少约 96.7%。周期边界仍需要真实换码，不能用普通倒计时的数字代替。单个缓存最多 10000 条，锁定清空 UI 码和索引；不强持旧模型、种子、Mac 或 OTP 参数。

真实 VM 测试用可控墙钟走完 30 秒：倒计时逐秒更新但只在周期变化时重新 HMAC；重复前台回调只保留一个延迟任务；后台宽限仅保留锁定 deadline，没有出码任务；锁定后缓存与延迟队列清空。没有后台资源采样服务。

以上证明本机趋势和确定性资源规则。手机冷启动、帧率、PSS 峰值、低端设备 KDF 时间、耗电、系统验证及厂商卸载行为仍需 [手机说明](../testing/m4-phone-test.md) 验证，不能承诺所有机型“性能完美”或覆盖率 100%。
