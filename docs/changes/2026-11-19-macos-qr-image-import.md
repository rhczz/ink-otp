# Mac 从图片添加二维码账号

## 为什么做

[Beta 2 的桌面验收](2026-11-19-macos-desktop-lifecycle.md)已覆盖设置链接、相机用途说明和备份文件选择。用户也能在不授予相机权限的情况下，从现有图片添加账号。这条路径还需验证系统文件面板交给 Vision 的图像能否正确进入预览并保存。

## 范围与验收

GitHub 托管 Mac 从已有公共 `otpauth` 用例生成测试图片。桌面 XCTest 从添加菜单进入系统图片选择器，核对单个二维码的账号参数，检查取消文件选择、取消预览、无二维码和多个账号二维码时原库不变，再保存有效账号并重新打开确认。对已发布 Beta 2 的 DMG 复验相同路径。图库图片和实体摄像头分别验收。

## 实际结果

[公开 Beta 2 安装包的 GitHub Actions 复验](https://github.com/rhczz/ink-otp/actions/runs/44472753339/job/135385926857)在 macOS 26.7.2 上通过。运行器从 GitHub Release 下载通用 DMG，核对 SHA-256 后安装。它先用 Beta 1 创建测试库，再覆盖安装 Beta 2。原有六项桌面用例和新增的二维码用例全部通过。

- 从系统面板选取单码图后，预览显示 GitHub、me@example.com、TOTP、SHA1、6 位和 30 秒。保存后库中只增加一个账号。退出并重新启动后，账号和全部参数仍可读取。
- 在系统面板按 Escape，或在已经识别账号的预览里点击取消，原有账号和总数保持一致。
- 空白图提示未识别到验证码二维码，双码图提示只能选择一个账号。两次操作都保留原库，也没有写入图片里的任一账号。

[测试证据](https://github.com/rhczz/ink-otp/actions/runs/44472753339/artifacts/14504669215)包含单独的二维码 XCTest 结果和完整日志。[macOS 15 的常规打包流程](https://github.com/rhczz/ink-otp/actions/runs/44472694751)也通过全部七项桌面测试，使用同一套用例验收从源码构建的通用 DMG。本次只增加验收工具和记录，公开下载继续使用已验证的 Beta 2。打包应用未插桩，桌面 UI 的源码行和分支覆盖率未验证。内核覆盖率见[跨端验收记录](2026-11-19-macos-cross-platform.md)。

实体摄像头扫码、Touch ID 与登录密码授权、VoiceOver 听感及首次下载后的 Gatekeeper 体验仍需在真实 Mac 上验证。复核时仓库未配置用于正式发布的 Apple 签名、公证凭据或自托管 Mac 运行器。每次进入时的系统身份验证仍受 [EX-008](../exceptions.md) 限制。
