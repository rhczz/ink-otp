# Android 进门验证、隐私与设置修复

## 为什么做

手机反馈指出，关闭「每次进入时验证身份」后重进仍会要求恢复口令。添加弹层有两根拖动条，剪贴板设置难以选择，诊断的两项操作也绑在了一起。本次同时补强屏幕隐私、梳理恢复口令的用途，并在开源许可中标明源码出处。

## 范围与验收方式

- 默认进门直接打开库。旧版首次升级在缺少可自动开的本机包装时，优先尝试已有系统认证，仅在需要迁移或修复时使用恢复口令。开启每次验证后，后台返回和冷启动使用 Android 系统验证，取消或失败保持锁定。覆盖旧版账号、无恢复口令、凭据失效及重建、前后台、旋转、系统选择器和手动锁定。
- 加号弹层最多一根拖动条。剪贴板清理弹出五项选择，验证应用复制、快速连续复制、写入另一应用内容、定时、手动锁定、关停和升级已有偏好。
- 保留正式包的安全窗口，补上最近任务缩略图、第三方悬浮窗和遮挡触摸保护。覆盖遮挡时不执行操作、无障碍和系统验证/文件选择器能正常使用。
- 许可页能打开 InkOTP 源码仓库。诊断重新计算验证码只更新验证码和时钟值，资源按钮只刷新资源统计，验证重复点击及离开页面的行为。
- 从新 `feature/` 分支提交 PR，待验证通过后合入 `master`。使用既有发布签名交付可覆盖安装的 APK，并核对实际签名。按 Makefile 运行验证并记录行、分支覆盖率，留出真机专项复核清单。

## 实际结果

旧版后台锁定会清掉内存会话，有恢复口令的库却没有供免验证策略使用的 Keystore 包装。因此后台返回和冷启动经常落到恢复口令表单。现在关闭开关时可通过设备上的加密包装重新打开库，已有库在首次有效认证后迁移。开启开关时由 Android 验证每次进入，取消或失败保持锁定。恢复口令继续用于备份、修改口令和必要的绑定恢复。验证开启时，改口令或确认备份导入会先取得新的系统授权，避免更新后要求再次用恢复口令绑定。若保存后的本机绑定写入中断，数据仍可通过恢复路径打开。使用的系统认证、恢复边界和设备包装见 [Android 交互规格](../../spec/android-interaction.md) 与 [本机库格式](../../spec/vault-format.md)。

加号打开的是一个弹层，原先共用底部容器和内容区各绘制了一根拖动条。现在只由容器绘制。开源许可区在 GPL-3.0 下增加源码仓库入口。诊断页的重算会重新生成当前 TOTP 并更新时钟值，资源刷新单独执行；重算保留原资源采样结果。

剪贴板设置提供五档单选，原有时长在主动修改前继续生效。清理前核对最近一次复制的随机标记和系统写入时间。例如复制验证码后，若另一应用写入同样的数字，原定时器会跳过这次清理。Android 提供分开的读取与清除接口，切后台、被系统结束或遇到其他应用同时写入时只能尽力处理。正式包沿用屏幕捕获保护，增加最近任务、悬浮窗、遮挡触摸和无障碍敏感内容保护。依据 [Android 遮挡触摸防护](https://developer.android.com/privacy-and-security/risks/tapjacking) 与 [Android 剪贴板接口](https://developer.android.com/reference/android/content/ClipboardManager#getPrimaryClipDescription())。

### 真机待复测

- 从旧签名 APK 覆盖安装。核对已有账号、设置和备份，分别验证开关关/开时冷启动、后台返回、手动锁定及系统文件选择器往返。用实际的指纹、手机锁屏凭据验证成功、取消与重新绑定。
- 核对 15/30/60 秒延迟、立即、关闭、跨应用粘贴及另一应用替换剪贴板。遇到系统禁止后台读取时观察实际清理表现。
- 核对截屏、录屏、最近任务预览、悬浮窗、TalkBack 和系统认证界面。Android 8–11 的独立弹层依赖平台自身能力，主窗口的触摸过滤不覆盖这些独立窗口。
- 核对加号拖动手势、外部浏览器跳转及诊断按钮各自执行。真机覆盖升级与硬件保护目前未验证。
