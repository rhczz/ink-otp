# Mac 切换应用、解锁与添加账号

## 为什么做

[桌面 Beta 1](2026-11-18-macos-native-parity.md) 在返回验证码库、隐藏窗口内容和手动输入设置链接时，与 Android 0.5.3 存在可见差异。本次以 [Android 交互规则](../../spec/android-interaction.md) 为基准修正桌面行为。

## 原来怎样

未开启每次进入验证时，后台超时后回到桌面窗口需要再点一次解锁。失焦到锁定之间仍可看见账号名称与已打开的弹层。手动添加支持 Base32，完整设置链接需要从另一个菜单进入。

## 范围与验收

在 GitHub Actions 验证普通自动锁定后返回、手动锁定后的保持锁定、隐藏账号和弹层、完整设置链接的字段解析。使用相同的设备钥匙串授权规则，恢复路径继续遵守既有系统身份验证策略。发布后检查通用 DMG 与校验文件。真实设备的 Touch ID、相机权限和辅助功能体验分别记录。

覆盖升级还需验证临时签名变化后，原恢复口令能重新绑定普通设备钥匙串。自动解锁不应卡在后台的钥匙串授权框。主动点击解锁时保留系统钥匙串授权入口，供没有设置恢复口令的旧用户尝试打开其已有设备绑定。错误口令、绑定失败或退出时应保留原库及恢复能力。

另以 Android 发布标签中的 `VaultActions`、`ItemDetailScreen`、`VaultViewModel` 核对三条行为。启用隐藏时只能通过设置恢复显示。HOTP 迁移后保留参数和计数器，不能在界面生成、复制或推进。授权窗口导致的后台宽限最长两分钟。用同一组公开的 HOTP 备份验证数据保真，在界面检查不可用操作。

诊断页的刷新按钮原来仅更新时间标签。本次纳入实际 TOTP 重算、与资源采样分离，以及关于页和相机权限说明中的离线隐私入口。检查阅读后返回不会触发相机授权。

## 实际结果

在 GitHub 托管的 macOS 桌面，从公开 Beta 1 的 DMG 新建库和测试账号，再用候选应用覆盖同一位置。[升级测试](https://github.com/rhczz/ink-otp/actions/runs/44458961485)确认原恢复口令可打开旧账号，手动设置链接的服务名、账号、SHA256、8 位和 60 秒均按预期显示。该次测试发现窗口遮罩已出现时，原生编辑框仍可在辅助功能树中找到，后续改为失焦时从窗口移除原生输入控件，并把草稿状态保留在编辑器中。[修复后的覆盖升级测试](https://github.com/rhczz/ink-otp/actions/runs/44460336402/job/135349159374)中，辅助功能隐藏、返回草稿、自动锁定和手动锁定这一组操作全部通过。

两种架构的内核覆盖率见[跨端记录](2026-11-19-macos-cross-platform.md)。已打包应用的桌面测试没有插桩，未测其源码行及分支覆盖率。真实 Mac 的 Touch ID、登录密码授权与取消、相机扫码、VoiceOver 听感和 Gatekeeper 首次打开均未验证。
