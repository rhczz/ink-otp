# Mac 切换应用、解锁与添加账号

## 为什么做

[桌面 Beta 1](2026-11-18-macos-native-parity.md) 在返回验证码库、隐藏窗口内容和手动输入设置链接时，与 Android 0.5.3 存在可见差异。本次以 [Android 交互规则](../../spec/android-interaction.md) 为基准修正桌面行为。

## 原来怎样

未开启每次进入验证时，后台超时后回到桌面窗口需要再点一次解锁。失焦到锁定之间仍可看见账号名称与已打开的弹层。手动添加支持 Base32，完整设置链接需要从另一个菜单进入。

## 范围与验收

在 GitHub Actions 验证普通自动锁定后返回、手动锁定后的保持锁定、隐藏账号和弹层、完整设置链接的字段解析。使用相同的设备钥匙串授权规则，恢复路径继续遵守既有系统身份验证策略。发布后检查通用 DMG 与校验文件。真实设备的 Touch ID、相机权限和辅助功能体验分别记录。

覆盖升级还需验证临时签名变化后，原恢复口令能重新绑定普通设备钥匙串。自动解锁不应卡在后台的钥匙串授权框。错误口令、绑定失败或退出时应保留原库及恢复能力。

另以 Android 发布标签中的 `VaultActions`、`ItemDetailScreen`、`VaultViewModel` 核对三条行为。启用隐藏时只能通过设置恢复显示；HOTP 迁移后保留参数和计数器，不能在界面生成、复制或推进；授权窗口导致的后台宽限最长两分钟。用同一组公开的 HOTP 备份验证数据保真，在界面检查不可用操作。
