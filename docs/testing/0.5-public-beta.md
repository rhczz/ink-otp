# InkOTP 0.5 Android 公测

## 下载与覆盖更新

公测版本为 `0.5.0-beta.1`，应用内显示「公测版」。支持 Android 8.0 及以上，包名为 `io.github.rhczz.inkotp`，versionCode 为 7。从 GitHub Release 下载 `InkOTP-0.5.0-beta.1.apk`。如需在电脑上校验下载，把 APK、`SHA256SUMS`、`build-info.json` 和 `release-notes.md` 放在同一目录，再运行 `shasum -a 256 -c SHA256SUMS`。 [0.5.0-beta.1 下载](https://github.com/rhczz/ink-otp/releases/tag/v0.5.0-beta.1)

从官方签名的旧版升级时，先在旧版导出一份加密备份并确认记得对应口令，再点击新版 APK，选择系统安装界面的「更新」。保留旧应用和应用数据。系统若提示签名冲突或拒绝安装，先记下错误并核对安装包来源。卸载或清除数据会删除本机库及本机密钥，已主动导出的外部文件仍由你管理。

安装完成后先核对账号数、顺序、验证码和设置。旧版只有口令包装或旧生物识别绑定时，首次进入可能要求一次系统授权或应用恢复口令来建立新绑定。开启「每次进入时验证身份」的库继续使用 Android 系统认证。Android 8–10 使用系统锁屏凭据确认，Android 11+ 可使用系统允许的强生物识别或锁屏凭据。应用恢复口令在 InkOTP 内输入，手机 PIN、图案和密码只在 Android 系统界面输入。

## 备份与恢复

- 平时从设置选择「导出备份」，优先使用默认的 Aegis 加密 JSON。导出前需要设置本机恢复口令。保存文件与口令，换机前先用另一处可用环境确认备份可恢复。仍在使用的服务账号应保留服务方提供的备用码或其他登录方式。
- 新装或本机库无法打开时，使用「从备份恢复」。先在系统选择器选文件，在「打开加密备份」输入源应用导出时的口令。检查「恢复 N 个账号」预览中的格式、数量和兼容性提醒，选择「继续设置口令」并设置新的本机恢复口令。首启时点「恢复」。已有库时先看「替换本机库并恢复？」说明，再点「替换并恢复」。若此前启用每次进入验证，仍需 Android 系统授权。
- 救援替换前，App 保留一份原库密文在自己的私有目录。重复救援会更新这份副本，清除应用数据或卸载会删除它。无法安全保全时，App 会结束此次替换。救援库从本机默认设置开始，原来的加密备份仍使用原口令。
- 可在系统文件选择器或备份解密阶段取消。取消后不会提交账号，部分密钥派生需要等待底层计算返回。出现错误口令、不支持的格式或文件损坏提示时，保留原备份，从源应用重新导出或更换一份可用备份。
- 已解锁时仍可在设置导入，按预览选择合并或替换。导入会在本机重新加密。原来的手机密钥、系统认证绑定和来源 App 安全设置不会迁移。
- 支持 Aegis JSON、2FAS `.2fas`、多行 `otpauth://` 和旧 InkOTP `.2fab`。明文交换文件包含账号种子，避免在聊天、公开 issue 或分享链接中传输。Steam、7 位码等超出兼容范围的账号会使该文件明确报错。HOTP 条目可保留和再导出，日常出码仅支持 TOTP。 [格式与参数兼容表](../../spec/interoperability.md)

## 真机验收记录

**当前真机结果均为未验证。** 实机反馈时记录安装包版本、手机型号和 Android 版本。升级、重装与互通使用公开测试账号或备用环境。测试完成前，请保留旧验证器和已验证的备份。 [公开测试向量](../../spec/vectors.json)

| 专项 | 测试步骤与验收预期 | 状态 |
|---|---|---|
| 覆盖升级 | 用官方 0.4.3 APK 建测试库，加入至少 5 条包含 SHA256、8 位与非 30 秒周期的 TOTP，调整顺序和隐私设置并导出加密备份。先取消一次系统更新并确认旧版还能出码，再完成更新。核对列表顺序、验证码、恢复口令、隐藏码、自动锁定和剪贴板时限。尽量另测旧版设备绑定、口令独立和旧生物识别模式。 | 未验证 |
| 系统认证 | 在一台 Android 8–10 和一台 Android 11+ 设备上分别查看开关关、开时的冷启动与后台返回。认证成功进入，取消或失败留在锁定页，旋转及返回不会造成重复弹窗。开启每次进入验证后，在测试设备变更指纹或锁屏凭据，检查可重绑时仍要求系统授权和恢复口令。 | 未验证 |
| 备份与灾备 | 先在备用环境恢复旧 `.2fab`、Aegis 和 2FAS。用已验证备份跑一遍卸载重装后的首启恢复，再换设备恢复，核对账号、参数与同一周期的码。把备份副本截断、输错口令，以及在文件选择、解密、预览、系统验证或最终确认环节退出，检查现有库不被覆盖。本机库损坏的故障演练限测试环境。 | 未验证 |

## 反馈和隐私

普通问题请在 GitHub Issues 提交，附应用版本、手机型号、系统版本、复现步骤、预期和实际现象。升级问题再附起始版本、原认证模式及失败环节。测试示意图使用公开测试账号并遮挡私有内容。 [普通问题反馈](https://github.com/rhczz/ink-otp/issues)

涉及验证码泄露、绕过锁定或备份安全，请走私下安全报告并参照安全政策。反馈附件请避开真实验证码、二维码、种子、手机锁屏凭据、恢复口令和备份。 [私下报告漏洞](https://github.com/rhczz/ink-otp/security/advisories/new) · [安全报告指引](../../SECURITY.md)

InkOTP 在手机本地生成验证码，没有联网权限、遥测或自动崩溃上报。相机权限只用于扫码，图片和备份文件都通过 Android 系统选择器由你选取。关于页中的源码链接由外部浏览器打开。后台、系统结束进程或其他应用同时写入时，剪贴板清理受 Android 系统行为限制。 [威胁模型](../threat-model.md)
