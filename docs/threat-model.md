# 威胁模型（v1.0 Android）

> 配套设计文档 §6.6。本文只列 v1.0 实际实现的边界与不防御项；格式/密钥细节见 `spec/vault-format.md`、`spec/backup-format.md`。

## 1. 资产

| 资产 | 位置 | 泄露后果 |
|---|---|---|
| 种子 secret | 库 JSON 明文只在解锁内存；磁盘为密文 | 直接接管所有账号的 2FA |
| DEK / KEK | 仅解锁期内存；DEK 由 Keystore 或口令包装 | 解开整库 |
| 当前验证码 | UI 内存/剪贴板 | 30 秒内可冒用 |
| 账号元数据（issuer/account/排序） | 库 JSON（加密） | 暴露账号清单，本身敏感 |
| 备份和交换文件 | 用户通过系统选择器指定的位置 | 加密格式仍可离线猜口令；明文格式直接包含种子 |
| 恢复口令 | 用户记忆/密码管理器 | 同时解开库与备份 |

## 2. 信任边界

1. **App 进程 ↔ Android 系统/Keystore**：Keystore 密钥不出安全硬件/系统；生物识别由系统完成。
2. **App ↔ 用户**：用户可能跳过口令、使用弱口令、把备份与口令放在一起。
3. **App ↔ 文件选择器/备份位置**：备份文件离开 App 私有目录后由用户负责。
4. **App ↔ 相机/相册**：二维码图片是外部输入，按不可信解析。
5. **App ↔ 系统备份/换机**：库文件与 Keystore 密文排除自动备份，避免“假恢复”。
6. **构建 ↔ 依赖**：供应链是信任边界；依赖最小化、锁定版本。

## 3. 威胁与缓解

| 威胁 | 场景 | 缓解 | 残余风险 |
|---|---|---|---|
| 设备丢失/被拿走 | 捡到者打开 App | 生物识别/口令；进后台锁定；FLAG_SECURE；库全密文 | 降级 device 模式下无锁；root 设备 |
| 肩窥/截屏 | 旁人看到验证码 | release FLAG_SECURE；默认不隐藏码但可开启“隐藏验证码直到点击” | 物理肩窥无法防 |
| 恶意 App 读剪贴板 | 复制后其他 App 读取 | API 33+ 标记 sensitive；30s/立即清理；手动锁定清理；后台自动锁库保留短暂粘贴窗口（ADR-024） | 系统剪贴板预览；进程被杀时清理不保证 |
| 恶意输入法/无障碍 | 手动输入 secret | 安全输入框、禁用自动更正；不支持无障碍拦截 | Android 无法完全防御恶意 IME；文档明示 |
| 备份泄露 | 备份发到聊天工具/网盘 | 默认 Aegis scrypt 加密，2FAS 按官方 PBKDF2 参数互通。明文文件和 Google 迁移码须单独确认 | 弱口令可离线爆破；2FAS 迭代数较低；明文没有加密保护 |
| 备份被篡改 | 恶意或损坏的交换文件 | AEAD 先验证后解析；头部参数上限；逐字节篡改测试 | 无 |
| 时钟被篡改 | 用户改时间/时区 | wall vs monotonic 漂移检测 + 诊断页 | 不联网对时，不自动校正 |
| 系统备份/云同步 | 库文件进入云备份 | `allowBackup=false` + `dataExtractionRules` 全排除 | 用户自行复制文件 |
| 供应链投毒 | 依赖被替换/恶意包 | 依赖白名单、版本锁定、M4 生成 verification metadata；无分析 SDK | 无法证明构建完全可复现 |
| 生物识别变更 | 新增/删除指纹 | `setInvalidatedByBiometricEnrollment(true)` + 口令回退 + 重新绑定 | 部分 ROM 行为不一致 |
| 每次进入验证被绕过 | 包装删除、改口令、导入后旧入口仍解锁 | 独立持久策略；旧入口全部拒绝；关闭需新系统证明；重绑需系统证明与应用恢复口令 | API 26–29 使用系统短时认证密钥和新 Keyguard 结果组合；硬件与 ROM 待实测 |
| 交换输入资源耗尽 | 恶意 JSON、scrypt 参数、超长 Base64 或账号列表 | 12 MiB 文件、JSON 深度/容器预算、10000 账号、64 MiB scrypt 上限和最多 4 个口令槽；整份拒绝不支持条目 | 有限预算内的解密仍会占用 CPU/内存 |
| 降级模式滥用 | 用户跳过口令与生物识别 | 常驻警告；device-bound Keystore；可随时升级口令 | 拿到已解锁手机的人可直接打开 App |
| root/越狱 | 系统级读取内存 | 不阻断；文档声明局限 | 无法防御 |
| 屏幕快照/最近任务 | 多任务预览 | release FLAG_SECURE | 系统截屏工具在极少数 ROM 上仍可能成功 |

## 4. 明确不防御

- 已 root/越狱设备上的内存读取、调试注入。
- 用户遗忘恢复口令；设计上不可恢复。
- 用户把备份与口令放在同一不安全位置。
- 物理胁迫、肩窥、摄像头对屏幕拍摄。
- 恶意系统输入法/无障碍服务在手动输入 secret 时的记录。
- 系统级截屏绕过（部分定制 ROM）。

## 5. 内存与日志纪律

- secret/DEK/KEK/验证码不进入日志、崩溃信息、错误文案、第三方 SDK。
- 锁定时清空引用；JVM/ART 无法保证物理擦除，作为已知局限声明。
- 不引入分析/崩溃上报 SDK；错误只报类别/错误码。
- UI 层只持有验证码字符串 + 剩余秒数，不持有 secret。
- 敏感状态不放进 `SavedStateHandle`/`rememberSaveable`。
- 交换结果只在当前会话内存中暂存；取消、锁定或过期会清理字节与导入种子。外部明文文件只在用户明确确认后写入用户选定位置。
- 诊断只按需汇总内存、私有文件大小和耗时，不含账号、种子、验证码、口令或完整文件路径；不产生遥测和后台监控。
