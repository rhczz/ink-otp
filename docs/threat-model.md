# InkOTP 威胁模型

InkOTP 将账号密钥和账号资料保存在本机加密库。应用解锁后，需要在进程内使用密钥来出码。设备信任边界包括操作系统、系统认证与密钥存储。备份和迁移还涉及用户选用的文件提供商或目标验证器。 [本地库格式](../spec/vault-format.md) · [本地库与交换格式](platform-neutrality.md)

## 需要保护的数据

| 数据 | 泄露的影响 |
| --- | --- |
| 账号密钥及出码参数 | 可持续生成对应账号的验证码，直至服务端撤销并重新绑定。 |
| 当前验证码 | 可能在服务端接受的时间窗口内被使用。验证码暴露后是否能重放由服务端决定。 |
| 账号标签、备注等资料 | 可能暴露用户使用的服务和账号关系。 |
| 库加密密钥和恢复口令 | 库密钥可解密对应库。恢复口令用于本机库恢复，也可能是某一份导出的加密备份所用的口令。 |
| 导出的文件和迁移二维码 | 加密文件可被离线尝试猜测口令。明文文件和迁移二维码包含可出码的密钥。 |

## 设备内的保护

Android Keystore 保护设备包装。开启每次进入验证时，Android 11+ 由系统提供强生物识别或锁屏凭据，Android 8–10 使用系统锁屏确认和限时密钥。发布版按隐私配置限制截屏和任务快照，Android 12+ 可隐藏非系统悬浮窗。具体效果依赖系统版本和设备。 [Android 交互规格](../spec/android-interaction.md)

本机库保存在应用私有位置并配置排除系统自动备份。锁定时清理会话和出码缓存。托管运行时与系统框架中的历史拷贝无法保证逐字节擦除。日志、诊断和错误文案排除凭据与验证码。

复制验证码会把短码交给系统剪贴板。应用按设置清理自己写入的验证码，其他程序仍可能在清理之前读取。系统提前终止进程时，定时清理也可能无法执行。 [Android 剪贴板设计 ADR-024](design/2FA验证器-技术设计文档.md#m3-实施决策2026-11-17)

## 导入、导出与设备恢复

- 导入文件、链接和二维码按外部输入处理。应用限制数据大小、账号数量和 KDF 成本，加密格式通过认证后再使用内容。导入时先预览，确认后才写入账号库。 [交换规格](../spec/interoperability.md)
- 常规备份默认使用口令加密的 Aegis JSON。2FAS 使用其格式要求的派生参数。明文文件和 Google Authenticator 迁移二维码在确认后才导出，获得这些内容的人可以继续出码。 [格式与兼容](standards-and-interoperability.md)
- 导出文件的持久副本由用户和目标文件提供商管理。卸载应用不会删除用户另存的备份。更改本机恢复口令后，之前导出的备份仍使用导出时的口令。
- 丢失设备时，可以用仍可解密的加密备份恢复账号。若设备、密钥和可用备份都已丢失，恢复登录要依赖各服务的备用码或账号恢复流程。

## 剩余风险

系统被 root 或注入调试代码后，攻击者可能读取解锁会话。系统输入法或无障碍服务可能记录手动输入的密钥。肩窥、外部拍摄、剪贴板读取和钓鱼也可能暴露密钥或短码。TOTP 的服务端校验和短有效期限制部分重放风险，钓鱼站仍能实时转发尚未使用的验证码。 [TOTP 原理与服务端校验](totp.md)
